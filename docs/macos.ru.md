# Сборка и установка на macOS

[README](../README.ru.md) · [English](macos.md) · [Проверки](macos-validation.md)

**mitm gui — автор SPomodor. Лицензия ISC.**

Подготовлены отдельные сборки **arm64** для Apple Silicon и **x64** для Intel с нативным Python-движком. Гибридной и universal-сборки для macOS нет. Собирать нужно на Mac соответствующей архитектуры: PyInstaller не компилирует между ОС, а упаковка движка другой архитектуры явно запрещена.

Локальные проверки выполнены на **macOS 15.8.1, Apple Silicon**. Для Intel проверена загрузка полного набора бинарных Python-зависимостей; выполнение x64 требует CI. Нижняя граница в настройках пакета — **macOS 14**, но эта версия отдельно не проверялась. Electron 44 указывает минимум macOS 13; проект намеренно задаёт более узкий диапазон. Настроенный CI сам по себе не является подтверждением поддержки. Результаты перечислены в [отчёте](macos-validation.md).

## Установка

Для Apple Silicon выберите `mitm-gui-<версия>-mac-arm64.dmg`, для Intel — `...-mac-x64.dmg`. Откройте DMG, перенесите **mitm gui.app** в «Программы», извлеките образ и запустите приложение из «Программ». ZIP содержит тот же полный пакет. Движок отдельно перемещать нельзя. Для подходящей нативной сборки Node.js, Python и Rosetta не нужны.

Сверьте `shasum -a 256` с `SHA256SUMS-mac-<архитектура>.txt`. Без Apple credentials применяется **ad-hoc подпись для целостности пакета**: она не подтверждает издателя, notarization отсутствует. Gatekeeper может заблокировать скачанную копию. Проверив источник и контрольную сумму, попробуйте запустить приложение и используйте «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть», если политика Mac разрешает это. Не отключайте Gatekeeper глобально. На управляемом Mac может требоваться администратор. Локальная сборка не проверяет quarantine-поведение скачанного файла.

## Системный прокси и сертификат

Приложение **не меняет и не восстанавливает** системный прокси, не устанавливает CA и не включает доверие автоматически.

1. Запустите HTTP-перехват и запомните порт, по умолчанию `8080`.
2. Откройте «Системные настройки → Сеть → активное подключение → Подробнее → Прокси». Сохраните прежнюю конфигурацию. Для **Веб-прокси (HTTP)** и **Защищённого веб-прокси (HTTPS)** укажите `127.0.0.1` и порт HTTP-слушателя. Авторизация не нужна. Оба пункта используют один обычный HTTP CONNECT-прокси.
3. Можно настроить только тестовый браузер или клиент: `curl --proxy http://127.0.0.1:8080 http://example.com/`.
4. Для HTTPS нажмите **Сохранить CA**, импортируйте публичный сертификат в **Связку ключей**, связку «Вход», проверьте сертификат mitmproxy и явно установите «Всегда доверять» для SSL. macOS может запросить аутентификацию. Используйте CA только собственного профиля. Приложение не включает доверие от вашего имени.
5. Включите расшифровку нужных хостов. После смены списка переподключите клиент.
6. **Перед выходом или остановкой перехвата восстановите прежние HTTP/HTTPS-прокси**, иначе подключённые клиенты могут потерять доступ в сеть. По окончании удалите импортированный CA или сбросьте его доверие, не затрагивая другие сертификаты.

Сохранённый `.cer` имеет формат PEM. Для отдельного клиента можно использовать `--cacert /путь/mitm-gui-ca.cer`, не меняя системное доверие. Интеграционные тесты используют временный CA и не меняют Связку ключей.

Для телефона укажите доступный LAN-адрес Mac, разрешите локальную сеть и следуйте существующим инструкциям Android/iPhone. macOS может запросить доступ к локальной сети или разрешение брандмауэра; выдавайте его только для нужных сетей.

## WireGuard и ограничения

Встроенный WireGuard-слушатель работает по UDP, по умолчанию `51820`, и создаёт профиль/QR для **одного внешнего устройства одновременно**. Отдельный сервер, root и привилегированный helper не нужны. Локально проверяются запуск слушателя, создание профиля и синтетические UDP/QUIC/DTLS-сценарии. Подключение физического телефона и его VPN-маршрутизация здесь не проверялись.

Доступны HTTP-прокси и WireGuard. Перехват локальных процессов/transparent capture macOS не предоставляется; redirector mitmproxy не устанавливается как системное расширение. Наличие платформенной зависимости не означает доступность этих режимов. IPv6 WireGuard ограничен; VPN, изоляция Wi-Fi и брандмауэр могут мешать соединению. Используйте стандартные непривилегированные порты; не запускайте всё приложение от root.

## Окна, клавиши и данные

Сохранены нативные кнопки окна и заголовок macOS, область бренда позволяет перетаскивать окно. Закрытие главного окна скрывает его и оставляет перехват работающим. Dock возвращает окно. **mitm gui → Завершить / Cmd+Q** закрывает редакторы, архивирует сессию и завершает движок. При выходе сохраняется предупреждение о несохранённом сценарии.

Cmd+K — поиск трафика, Cmd+F — поиск в теле/скрипте, Cmd+S — сохранение. Меню редактирования поддерживает копирование, вставку и отмену. Ctrl+M, затем Tab позволяет выйти из редактора клавиатурой; нативное сочетание CodeMirror Option+Shift+M также сохранено. Русский/английский языки и темы работают.

Новый профиль: `~/Library/Application Support/mitm-gui`. При наличии старого CHLS-профиля он используется повторно. Лог движка находится в `engine/engine.log` внутри профиля. База, CA и ключи WireGuard хранятся вне `.app`. Делайте резервную копию только после завершения приложения.

## Сборка и CI

Нужны нативные **Node 24**, **Python 3.13** и Xcode Command Line Tools. Архитектуры Python, Node и Mac должны совпадать.

```sh
PYTHON=python3.13 npm run setup
npm run build
npm test
npm run test:format
npm run test:ui
npm run build:engine
CHLS_TEST_ENGINE="$PWD/runtime/mitm-gui-engine/mitm-gui-engine" .venv/bin/python -m pytest tests/test_integration.py -q
npx electron-builder --mac --arm64 --dir --publish never
npm run test:architecture
node scripts/smoke-ui.cjs --packaged
node scripts/smoke-language.cjs
node scripts/smoke-script-editor.cjs --packaged
node scripts/smoke-macos-lifecycle.cjs
npx electron-builder --mac dmg zip --arm64 --prepackaged "release/mac-arm64/mitm gui.app" --publish never
```

На Intel замените `--arm64` на `--x64`, `release/mac-arm64` на `release/mac`. `npm run package:mac` сразу создаёт DMG/ZIP для архитектуры хоста. Проверка архитектуры читает Mach-O заголовки через `lipo`, включая нативные Python-модули. Smoke-тесты используют отдельные профили. Lifecycle-тест проверяет наличие нативного пункта Quit и вызывает `app.quit()`: клавиши через CDP не вызывают AppKit-акселератор Cmd+Q. Физическое нажатие клавиш и клик Dock остаются пунктами ручной проверки релиза.

CI использует `macos-15` (arm64) и `macos-15-intel` (x64), соответствующие Node/Python, тесты исходников, скомпилированного движка и `.app`. Создаёт DMG/ZIP и SHA-256. Windows x64/ARM64 сохранены. Релиз по тегу ожидает успешных проверок обеих ОС и всех архитектур. В ходе локальной работы CI и публикация релиза не запускались.

## Подпись Developer ID и notarization

Для ad-hoc сборки secrets не нужны. Для полноценного релиза добавьте Actions secrets:

| Secret | Содержимое |
| --- | --- |
| `MAC_CSC_LINK` | Экспорт Developer ID Application `.p12`, кодированный base64 |
| `MAC_CSC_KEY_PASSWORD` | Пароль экспорта |
| `APPLE_ID` | Email Apple Developer |
| `APPLE_APP_SPECIFIC_PASSWORD` | Пароль приложения для notarization |
| `APPLE_TEAM_ID` | Идентификатор команды |

Установите Actions variable **`MITM_GUI_NOTARIZE=true`**. CI передаёт первые два секрета как `CSC_LINK` и `CSC_KEY_PASSWORD`; для локальной подписанной сборки используйте именно эти имена плюс Apple-переменные. Не добавляйте значения в Git и логи. Для репозитория с недоверенными branch workflows используйте защищённое окружение релиза; fork PR не получает secrets.

С credentials electron-builder подписывает пакет и вложенный код с hardened runtime и JIT entitlement. After-sign hook вызывает `@electron/notarize`/notarytool, ожидает принятия и прикрепляет ticket к `.app` перед упаковкой. Без явного флага notarization не запускается; запрос без credentials завершает сборку ошибкой. Локальные артефакты **не проверены** с Developer ID, notarization и Gatekeeper. Для подписанного релиза проверьте установленный пакет командами `codesign --verify --deep --strict`, `xcrun stapler validate`, `spctl --assess --type execute --verbose`, затем запуск движка и Python-workers.
