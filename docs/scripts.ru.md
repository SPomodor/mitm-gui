# Скрипты mitm gui 0.8

Основа — обычный Python. mitm gui предоставляет модуль `chls` внутри процесса скрипта.
Сценарий со состояниями — дополнительный API поверх тех же обработчиков.
На компьютере пользователя отдельная установка Python не требуется.

## Редактор

В 0.8.3 редактор поддерживает подсветку Python, номера строк и поиск.

- Tab / Shift+Tab — добавить / убрать один уровень отступа у строки или выделенного блока.
- Отступ — четыре пробела, чтобы не смешивать табуляцию и пробелы в Python.
- Enter — новая строка с автоматическим отступом.
- Ctrl/Cmd+Z — отмена, Ctrl+Y или Ctrl/Cmd+Shift+Z — повтор.
- Ctrl/Cmd+F или «Найти» — поиск без учёта регистра, с подсветкой и счётчиком.
- Enter / Shift+Enter в поиске — следующее / предыдущее совпадение, Esc — закрыть.
- Ctrl+M, затем Tab — переход из редактора к другим элементам с клавиатуры.

В интерфейсе — библиотека и выбор папки JSON. Область и поведение задаются в коде.
Переключение разделов и изменение размеров панелей
сохраняют черновик, позицию курсора и историю отмены. Редактор загружается при первом
открытии раздела. Поиск работает и за пределами видимой части большого скрипта.

## Библиотека сценариев (0.8.5)

Каждая запись хранит название, Python-код и папку JSON. Поле поиска фильтрует
список, выпадающий список открывает сценарий в редакторе. «Новый» и «Пример»
создают независимую запись на основе `../examples/basic/scenario.py`.

- Название меняется прямо в поле над редактором; «Сохранить» или Ctrl/Cmd+S сохраняет
  изменения в библиотеку. Можно сохранять незавершённый код: он не выполняется.
- Кнопка копирования создаёт отдельный сценарий с тем же кодом и папкой JSON.
- Импорт `.py` / `.chls` создаёт запись; экспорт `.py` сохраняет исходник в выбранный файл.
  JSON-файлы не упаковываются в экспорт.
- При переключении, создании или импорте с несохранёнными правками можно сохранить
  их, отказаться от правок или отменить переход. При закрытии есть предупреждение.
- «Применить сценарий» проверяет код, устанавливает его в движок и сохраняет
  в библиотеку. Включение и сброс состояния относятся к применённому скрипту.
- Выбор, сохранение и удаление записи не меняют работающий скрипт.
- После перезапуска восстанавливаются библиотека и последний выбранный сценарий.
  Исполняемый скрипт, как прежде, запускается выключенным.

Библиотека находится в `script-library.json` в профиле приложения (рядом с `engine/`).
Старый единственный сценарий автоматически добавляется в библиотеку при первом
запуске новой версии. Пользовательский сценарий 187 сохраняется, но встроенной
кнопки и поставляемого шаблона 187 больше нет.

Учебный пример ограничен `example.com` и `/api/`. Откройте через HTTP-прокси mitm gui
`http://example.com/api/hello`: ответ содержит приветствие, счётчик и текущий этап.
`POST http://example.com/api/finish` переводит в «Готово», после чего доступен
`GET http://example.com/api/result`. Для HTTPS требуется расшифровка SSL для домена.

## Первый скрипт

Откройте «Сценарии», вставьте код, выберите папку JSON при необходимости,
нажмите «Проверить», «Применить сценарий», «Включить сценарий».

```python
from mitm_gui import Script, response

app = Script("Мои ответы")

@app.get("/api/order")
def order(request, ctx):
    ctx.state["calls"] = ctx.state.get("calls", 0) + 1
    body = ctx.load_json("order.json")
    body.set("time", 123)
    return response(200, json=body)
```

Сохраняйте исходник как `.py`. Верхнеуровневая переменная `app` обязательна.
Область задаётся только в коде:

```python
app = Script(
    "Мои ответы",
    hosts=["api.example.com"],
    path_prefix="/api/",
    unmatched="forward",
)
```

Все параметры необязательны. Без `hosts` (или с `hosts=[]` / `["*"]`) подходят все
домены. Без `path_prefix` подходят все пути (`"/"`). `unmatched="forward"` передаёт
необработанные запросы обычным правилам и серверу; `"block"` возвращает для них
501 с `CHLS_SCRIPT_UNHANDLED` внутри области. Префикс ограничивает весь скрипт,
включая обработчики ответа, и проверяется по границе сегмента: `/api/` не включает `/api-other`.
Домены — до 20 точных имён/IPv4, без схемы и порта, либо `"*"` для всех.

Также можно присвоить `app.hosts`, `app.path_prefix`, `app.unmatched` после создания
`Script`. Настройки фиксируются при проверке/применении. В запросе `/mocks`
принимаются только `source` и `folder`; старые внешние `hosts`, `scope`, `strict`
отклоняются. GET возвращает вычисленную область в `policy` для диагностики.

Сохранённые Python-документы старого формата автоматически получают видимые
присваивания области в конце исходника. Учитывается прежний приоритет `app.hosts`
над внешним списком. Исходный файл настроек остаётся без изменений до применения;
новое сохранение содержит только версию формата 2, исходник и папку.
Сохранённый старый `.chls` переводится в Python вместе с настройками как выключенный
черновик; нужно проверить и применить его. Если перенос не удался, скрипт не активируется.

## Обработчики

- `@app.get(path)`, `@app.post(path)`, `@app.route(method, path)` — запросы.
- `@app.on_request` — обработчик любого запроса в области скрипта.
- Метод `"*"` подходит для любого метода; путь `"*"` — для любого пути.
- Пути точные, без query string. Query доступен отдельно.
- Первый подходящий обработчик выполняется один раз. Внутри группы действует
  порядок регистрации; обработчики текущего состояния приоритетнее общих.
- `return response(...)` создаёт локальный ответ. `return None` или
  `return forward()` передаёт изменённый запрос обычным правилам и на сервер.
  Это не переход к следующему обработчику скрипта.
- `@app.on_response` получает `(request, response, ctx)`. Все обработчики ответа
  вызываются по порядку. Можно изменить переданный ответ и вернуть `None` либо
  вернуть новый `response(...)`.
- Обработчики — обычные синхронные `def`. Асинхронные функции не поддерживаются.

```python
@app.on_response
def change_response(request, reply, ctx):
    if request.path == "/api/order":
        reply.json.set("time", 456)
        reply.headers["X-mitm gui"] = "modified"
        ctx.log("Время изменено")
```

У локальных моков обычные Rewrite ответа пропускаются. У ответов сервера сначала
выполняются обычные Rewrite, затем обработчики ответа скрипта. Переприменение
скрипта не запускает обработчик ответа новой версии для запросов старой версии.
После выключения скрипта ожидающие ответы им не обрабатываются.

## Запрос, ответ и JSON

`request` предоставляет `method`, `url`, `path` (только чтение), `query`
(словарь списков значений), `headers`, `text`, `content`, `json`, `client`.
Для изменения пути задайте полный `request.url`. `headers` поддерживает доступ
без учёта регистра. `reply` предоставляет `status`, `headers`, `text`, `content`, `json`.

`response(status, json=...)`, `response(status, file="order.json")`,
`response(status, text="...")`, `response(204)` создают ответы.
Одновременно задаётся только одно тело. Дополнительные заголовки — `headers={...}`.
Коды 200–599; 204/304 должны быть пустыми, HEAD отправляет только заголовки.

`ctx.load_json(file)` и `request.json`/`reply.json` возвращают объект `Json`:

```python
body = ctx.load_json("large-order.json")
old_time = body.get("time")
body.set("time", 100)
body.set("order.start.time", 200)
body.remove("debug")
body.set("/items/0/start/time", 300)
body.data["new_field"] = {"enabled": True}
return response(200, json=body)
```

Одинаковое разрешение селекторов используется в Rewrite → «Поле JSON»:

| Селектор | Поведение |
| --- | --- |
| `time` | Поиск имени во всём JSON, включая объекты внутри массивов |
| `order.start.time` | Точный путь от корня |
| `items.0.time` | Точный путь с индексом массива |
| `/order/start/time` | JSON Pointer; `~1` означает `/`, `~0` означает `~` внутри имени |
| `/literal.key` | Поле с буквальной точкой в имени |

Короткое имя должно совпасть ровно один раз, даже если одно из совпадений в корне.
При нескольких совпадениях ошибка перечисляет до пяти точных путей. При отсутствии
поля тоже возникает ошибка. Для добавления нового поля используйте точный путь
(например, `/time`); родитель уже должен существовать. Автоматического выбора
первого поля, массовой замены совпадающих имён и создания промежуточных объектов нет.
Значения сохраняют JSON-типы, включая числа, `False`, `None`, объекты и списки.

`Json.data` — обычный словарь/список Python. Каждый вызов `load_json` возвращает
отдельную копию; изменения не меняют снимок исходного файла.

## Сценарии

```python
from mitm_gui import Script, Scenario, response

app = Script("Доставка")
order = Scenario("order", initial="created")
app.use(order)

@order.get("/api/order", state="created")
def created(request, ctx):
    return response(200, json={"status": ctx.stage})

@order.post("/api/confirm", state="created")
def confirm(request, ctx):
    ctx.goto("confirmed")
    return response(201, json={"success": True})

@order.get("/api/order", state="confirmed")
def confirmed(request, ctx):
    return response(200, json={"status": ctx.stage})
```

Состояния объявляются через `initial` и аргументы `state` обработчиков.
`ctx.goto` проверяет существование состояния. Один `Scenario` на скрипт;
дополнительные данные можно хранить в `ctx.state`.
Нет режимов «Свободный / По сценарию», скрытых ответов и скрытого подавления
повторов. Повторный запрос снова запускает подходящий обработчик.

## Состояние и контексты

### Остановка из скрипта

`ctx.stop()` выключает **весь скрипт**, включая все контексты и обработчики.
Метод помечает остановку и не прерывает выполнение Python-функции: закончите
её обычным `return response(...)` или `return None`/`forward()`.

```python
@app.post("/api/complete")
def complete(request, ctx):
    ctx.state["completed"] = True
    ctx.stop()
    return response(200, json={"success": True})
```

Текущий запрос получает заданный ответ. С `return None` он передаётся обычным
правилам и серверу. Затем новые и уже ожидающие очереди обработчики этой версии
не выполняются. Включая обработчики ответа для остановленного запроса.

В `@app.on_response` команда сохраняет результат текущего обработчика и пропускает
последующие обработчики ответа. После ошибки функции, подготовки тела, заголовков
или состояния остановка не применяется. Кнопка и журнал обновляются автоматически.

Состояние и выбранный этап сохраняются; «Включить сценарий» возобновляет обработку.
Для нового прохождения сначала сбросьте состояние. В текущем исходнике шаблона 187
остановка добавлена при подтверждении этапа «Передать заказ»: ответ dropoff отправляется,
а дальнейший возврат обрабатывается настоящим сервером. Для обновления уже сохранённого
скрипта откройте актуальный `../examples/order-187/scenario.py` и примените его.

### Переменные

`ctx.state` — JSON-совместимый словарь, `ctx.stage` — текущее состояние сценария.
По умолчанию контекст общий. Для разделения по устройству:

```python
app.session_key = lambda request: request.headers["X-Device-Id"]
```

Можно выбрать `request.client` или идентификатор заказа, но ключ должен надёжно
идентифицировать нужный процесс. Ключ — непустая строка до 200 символов.
Отсутствующий обязательный заголовок вызывает явную ошибку, а не смешивает клиентов.
Обработчик ответа использует ключ, выбранный при запросе.

Интерфейс показывает состояние последнего обработанного контекста и их количество.
Ручной выбор этапа меняет последний контекст; «Сбросить состояние» очищает все
контексты. Состояние не сохраняется на диск. Применение и перезапуск начинают
его заново; после перезапуска модуль выключен.

Управляемое состояние, этап и изменения сообщений фиксируются после успешной
подготовки результата. Ошибка откатывает текущий вызов, включая все обработчики
одной фазы ответа. Это не транзакция внешних файлов, сетевых запросов или обычных
глобальных переменных Python. Для сбрасываемого состояния используйте `ctx.state`.

## Файлы, ошибки и выполнение

Файлы JSON загружаются и проверяются при запуске новой версии. Литеральные имена
в `load_json("file.json")` и `response(file="file.json")` обнаруживаются автоматически.
Вычисляемые имена перечислите в `app.files = ["one.json", "two.json"]`.
Файлы должны находиться внутри выбранной папки. После изменения примените скрипт заново.

Каждая версия исполняется в отдельном процессе. Инициализация ограничена 10 секундами,
вызов обработчика — 2 секундами. Тайм-аут завершает процесс; для восстановления
нужно применить скрипт заново. Работа остальных запросов и API mitm gui продолжается.
Ошибка запроса возвращает 500 `CHLS_SCRIPT_ERROR`. Ошибка обработчика ответа
сохраняет исходный для этой фазы ответ. Подробности доступны в журнале и trace запроса.

Ограничения: исходник 200 000 символов, 1000 обработчиков, тело/один JSON-файл 8 MiB,
снимок файлов 64 MiB, состояние контекста 1 MiB, все контексты 4 MiB, 1000 контекстов,
журнал 200 записей. Тела потоковых сообщений скриптами не обрабатываются.

Это полноценный Python с доступом к системе, а не изолированная среда безопасности.
Используйте доверенные скрипты. «Проверить» тоже выполняет верхнеуровневый код.
Произвольные сторонние Python-пакеты не включаются в portable автоматически.

## Переход с .chls

Старый сохранённый документ остаётся на диске. При первом открытии он переводится
в Python вместе с областью действия и показывается выключенным черновиком.
Для отдельно открытого файла .chls используйте кнопку «Перевести в Python».
Проверьте его, особенно ответы переходов: явно указанный ответ теперь сохраняется,
а не заменяется пустым 200. Удалена прежняя неявная защита от повторов.

Новый применённый документ сохраняется в `script-module.json`; старый
`mock-module.json` используется только как источник миграции. Исторический шаблон заказа остаётся только в исходниках:
`../examples/order-187/scenario.py`. В приложение он не включается.

С версии 0.8.1 шаблон 187 использует `<выбранная папка>/187/*.json`.
`exchange/init` возвращает pickup для первых трёх этапов, dropoff для
«К клиенту»/«Передать заказ» и complete для «Вернуться»/«Завершён».
В журнале `→ сервер` означает явную передачу запроса без локального ответа.
