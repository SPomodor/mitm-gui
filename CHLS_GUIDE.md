## 1. Что такое CHLS

CHLS — настольный отладочный HTTP/HTTPS-прокси на базе mitmproxy, по назначению похожий на Charles. Основной сценарий — просмотр и подмена сетевых запросов собственных приложений: Android, iPhone, браузеров и desktop-клиентов.

Готовая сборка предназначена для **Windows x64**. Интерфейс построен на Electron, React и TypeScript. Python-движок поставляется вместе с приложением: для запуска готового EXE отдельно устанавливать Python или Node.js не требуется.

Основные возможности:

- HTTP/HTTPS-прокси и WireGuard-сервер; их можно включать вместе или по отдельности.
- Просмотр запросов, ответов, заголовков, тел, исходных и изменённых сообщений.
- Rewrite, Map Local, Blocklist и упорядоченное выполнение правил.
- Один модуль сценариев: общие ответы, этапы заказа и HTTP-триггеры переходов.
- Запись трафика отдельно от работы прокси и отдельно от расшифровки HTTPS.
- Сессии с автоматическим архивированием, переименованием, удалением и экспортом HAR.
- Поиск по трафику, поиск внутри тела, фокус по доменам.
- Виртуализированный просмотр больших тел и Pretty для обрезанного JSON.
- Изменяемые размеры рабочих областей, светлая/тёмная/системная тема.
- Редактирование правил в отдельных немодальных окнах.

CHLS не включает системный прокси Windows автоматически и не устанавливает сертификат в доверенные автоматически.

## 2. Запуск и первые действия

### Готовые сборки

| Вариант                  | Путь относительно проекта             |
| ------------------------ | ------------------------------------- |
| Portable EXE             | `release/0.5.6/CHLS-0.5.6.exe`        |
| Распакованное приложение | `release/0.5.6/win-unpacked/CHLS.exe` |

Для распакованного приложения нужна **вся папка `win-unpacked`**, а не только `CHLS.exe`: рядом находятся ресурсы Electron и движок. Portable EXE сам распаковывает необходимые компоненты при запуске. Пользовательские данные в обоих случаях хранятся в профиле приложения, а не просто рядом с EXE.

При обычном запуске:

1. Запускается локальный Python-движок.
2. Предыдущие сессии переводятся в архив, создаётся новая текущая сессия.
3. Запись новых запросов включается.
4. Перехват автоматически запускается с последними настройками HTTP/WireGuard.
5. Загружаются сохранённые правила и применённый документ сценария.
6. Модуль сценариев остаётся **выключенным**, а его этап возвращается к начальному.

На чистом профиле используются HTTP-прокси `8080/TCP` и WireGuard `51820/UDP`, оба способа включены. При последующих запусках приоритет имеют сохранённые настройки. Если порт занят, интерфейс остаётся доступен: можно исправить порт и повторить запуск перехвата.

Для первого запроса:

1. Открыть **«Подключить устройство»** в левой панели.
2. Настроить WireGuard либо HTTP-прокси на клиентском устройстве.
3. Для HTTPS установить CA и включить его доверие там, где это требуется.
4. Убедиться, что перехват активен и запись включена.
5. Открыть приложение или страницу на подключённом устройстве.

## 3. Перехват, запись и SSL — три разные настройки

| Элемент интерфейса                           | Назначение                                                 | Что происходит при выключении                                                                                |
| -------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| **Перехват** со значком питания, слева внизу | Управляет HTTP/WireGuard-слушателями и соединениями        | Слушатели останавливаются, соединения закрываются. Подключённому клиенту может потребоваться переподключение |
| **Запись / На паузе**, сверху                | Управляет сохранением новых HTTP-запросов в текущую сессию | Прокси, правила и сценарии работают дальше, но новые запросы не сохраняются в историю                        |
| **Щит SSL**, сверху                          | Управляет расшифровкой HTTPS                               | Новые TLS-соединения идут без подмены сертификата; содержимое HTTPS недоступно для просмотра и подмен        |

### Запись

Красная точка и подпись **«Запись»** означают, что сохранение включено. Значок паузы и **«На паузе»** означают, что сохранение остановлено.

- Запрос, начатый при включённой записи, получает сохранённый ответ и после постановки записи на паузу.
- Запрос, начатый на паузе, не появляется задним числом после возобновления записи.
- При следующем запуске приложения запись снова включена.
- Включённая запись сама по себе не запускает остановленные слушатели.

### SSL

Щит с галочкой — расшифровка включена, перечёркнутый щит — выключена. Настройка сохраняется между запусками.

Изменение действует на **новые TLS-соединения**. Уже открытые соединения сохраняют прежний режим: после переключения переподключите приложение, браузер или туннель. При выключенной расшифровке обычный HTTP продолжает обрабатываться, а HTTPS-правила и HTTPS-сценарии не могут изменять зашифрованное содержимое.

Это настройка перехвата TLS, а не отключение проверки сертификата реального сервера.

## 4. Подключение через WireGuard

WireGuard удобен, когда требуется направить трафик телефона через CHLS без настройки Wi-Fi-прокси для каждого сетевого клиента.

1. Открыть **«Подключить устройство» → WireGuard**.
2. Включить WireGuard в настройках захвата. Для телефона в локальной сети нужен доступ из LAN.
3. Проверить UDP-порт; стандартный — `51820`.
4. Включить перехват. В качестве адреса компьютера выбрать IPv4 или hostname, доступный телефону. Пример: `192.168.1.10`.
5. Обновить QR-код после изменения адреса или конфигурации.
6. В приложении WireGuard на Android/iPhone добавить туннель по QR либо импортировать сохранённый `.conf`.
7. Включить туннель на телефоне.
8. Открыть **mitm.it** через этот туннель, скачать сертификат и настроить доверие для HTTPS.
9. Открыть нужное приложение и проверить появление запросов в CHLS.

Практические особенности:

- Один выдаваемый профиль рассчитан на **одно активное устройство одновременно**. Независимого менеджера peer-профилей пока нет.
- Профиль направляет IPv4; не следует считать, что весь IPv6-трафик также захвачен.
- Другой VPN на телефоне может конфликтовать с туннелем.
- QR-код формируется локально.
- Статус слушателя не является доказательством успешного WireGuard-handshake. Работу подтверждает наблюдаемый трафик.
- CHLS не добавляет правила брандмауэра Windows автоматически.
- Файл `.conf` содержит закрытый ключ клиента. Он нужен для подключения, а не для публичного отчёта об ошибке.

Если используется адрес компьютера с виртуального адаптера или VPN, телефон может его не видеть. Выберите адрес интерфейса, через который телефон действительно достигает компьютера.

## 5. Обычный HTTP-прокси

### Телефон

В настройках Wi-Fi выбрать ручной HTTP-прокси:

- сервер — доступный телефону IPv4 компьютера;
- порт — HTTP-порт CHLS, по умолчанию `8080`;
- аутентификация — выключена.

В CHLS должны быть включены HTTP-прокси, доступ из LAN и перехват. Клиент должен поддерживать и использовать эту настройку прокси: не каждое приложение учитывает системный Wi-Fi-прокси.

### Браузер или desktop-приложение на том же компьютере

Указать прокси `127.0.0.1:8080` в настройках клиента или его сетевого стека. Если выбран другой HTTP-порт, заменить `8080` на него.

Пример проверки через PowerShell:

```powershell
curl.exe --proxy http://127.0.0.1:8080 http://example.com/
```

Здесь `curl.exe` указан явно, чтобы не зависеть от возможного PowerShell-алиаса `curl`. Для просмотра HTTPS клиенту также потребуется доверие CA CHLS.

## 6. Сертификат, mitm.it и HTTPS

**mitm.it** доступен как страница выдачи CA, когда браузер устройства уже идёт через WireGuard или HTTP-прокси CHLS. Вводить можно `http://mitm.it`; в интерфейсе показывается короткое имя **mitm.it** без префикса.

Порядок действий:

1. Сначала подключить устройство к CHLS.
2. Открыть mitm.it в браузере этого устройства.
3. Выбрать свою платформу и скачать публичный CA.
4. Установить CA и настроить его доверие.
5. Открыть приложение и убедиться, что видны HTTP-запросы внутри HTTPS.

Альтернатива — кнопка **«Сохранить CA»** в CHLS и передача публичного сертификата на устройство. Экспортируется публичный сертификат, не закрытый ключ CA.

### Android

Переключатель **Android/iPhone** находится внизу окна подключения, рядом с инструкциями установки сертификата. Названия пунктов Android зависят от оболочки устройства; ориентируйтесь на установку сертификата CA в настройках безопасности.

Для собственного debug-приложения установки пользовательского CA может быть недостаточно: приложение должно доверять этому хранилищу. Пример для сетевого стека, поддерживающего Network Security Config:

```xml
<!-- res/xml/network_security_config.xml -->
<network-security-config>
    <debug-overrides>
        <trust-anchors>
            <certificates src="user" />
        </trust-anchors>
    </debug-overrides>
</network-security-config>
```

В `application` манифеста указать `android:networkSecurityConfig="@xml/network_security_config"`. Этот debug-раздел применяется при `android:debuggable=true`.

Если конкретная библиотека отдельно реализует certificate pinning, её debug-поведение нужно настраивать отдельно. Сам WireGuard pinning не отменяет.

### iPhone

После установки профиля сертификата нужно включить **полное доверие** CA в настройках доверия сертификатам. В окне подключения есть отдельная инструкция для iPhone. Одной загрузки файла сертификата недостаточно.

CA создаётся для профиля приложения. Если создать новый профиль CHLS с другим CA, клиентам понадобится доверие новому сертификату.

## 7. Просмотр трафика, поиск и большие тела

В таблице видны метод, домен и путь, статус, время, размер, а также индикатор применённых правил. Есть фильтры **Все / Изменённые / Ошибки**.

Поиск над таблицей учитывает URL, метод, статус и адрес клиента. **Ctrl+K** ставит курсор в этот поиск. Отдельная декоративная подсказка сочетания рядом с очисткой убрана в 0.5.6; сочетание осталось рабочим.

### Домены вместо адресов соединения

Для понятного отображения используются HTTP Host / HTTP/2 authority, затем TLS SNI. Если домен неизвестен, может остаться IP. Реальный адрес назначения соединения при этом не подменяется.

Правила из контекстного меню заполняются по исходным host/path/method запроса, даже если его URL уже был изменён другим правилом. Для старой истории домен по возможности восстанавливается из сохранённых данных.

### Инспектор

Выбрать запрос в таблице. В инспекторе:

- **Request / Response** — сторона сообщения;
- **Body / Headers / Правила** — содержимое, заголовки или журнал срабатываний;
- **Итог / Оригинал** — состояние после изменений или сохранённое исходное сообщение;
- **Pretty** — форматирование JSON;
- кнопка копирования — текст тела либо заголовки выбранной вкладки;
- кнопка скачивания тела — сохранённые исходные байты выбранной стороны/варианта.

Оригинал означает сообщение до обработки CHLS на соответствующей стадии. Данные могут отсутствовать у потоковых тел или незавершённых/оборванных запросов; это не выдаётся за пустой успешно сохранённый ответ.

### Поиск внутри тела

**Ctrl+F** открывает поиск в теле выбранного Request/Response. Из Headers он переключается на Body.

- Поиск буквальный, без regex, без учёта регистра.
- Ищется по всему загруженному превью, включая строки за пределами экрана.
- Есть счётчик и подсветка.
- **Enter / Shift+Enter** — следующее / предыдущее совпадение.
- **Esc** — закрыть поиск.
- Учитываются первые 10 000 совпадений; при достижении лимита отображается `+`.

### Большие тела

Текстовое превью ограничено первыми **256 KiB** декодированного тела. Поэтому сжатый ответ размером меньше 256 KiB в таблице тоже может иметь обрезанное превью после распаковки.

Просмотр виртуализирован: в DOM создаётся только видимая часть с небольшим запасом. Очень длинные строки визуально переносятся; `↳` означает продолжение той же исходной строки. Подсветка работает с ограниченными фрагментами, результат Pretty кешируется, обычные клики не форматируют всё тело заново.

Pretty умеет форматировать и **обрезанный JSON-префикс**: добавляет отступы и переносы, сохраняя строки и экранирование. Недостающие значения и закрывающие скобки не достраиваются. Пометка об обрезанном превью остаётся.

Для копирования доступного текста целиком используйте кнопку копирования: выделение мышью в виртуальном списке не является способом получить все невидимые строки. Для полного сохранённого тела используйте скачивание. Pretty меняет отображение, а не сохранённые байты и не ответ клиенту.

## 8. Фокус по хостам

Фокус — сохранённый набор точных доменных имён для фильтрации таблицы.

1. Нажать значок фильтра рядом с хостом либо выбрать **«Добавить хост в фокус»** в контекстном меню запроса.
2. Переключить список на **«В фокусе»**.
3. Для полного списка выбрать **«Все хосты»**.

Переключение также сбрасывает выбор одного конкретного домена. Сам список отмеченных хостов сохраняется между запусками и общий для разных сессий. Положение переключателя при новом запуске возвращается к **«Все хосты»**.

Фокус не блокирует запросы и не останавливает их запись. Трафик остальных доменов продолжает проходить и сохраняться при включённой записи. Чтобы блокировать запросы, нужен Blocklist либо соответствующий строгий сценарий.

## 9. Сессии, архив, очистка и экспорт HAR

### Текущая сессия и архив

- При запуске создаётся новая сессия записи.
- При закрытии приложения текущая сессия архивируется.
- При создании новой кнопкой `+` предыдущая также архивируется.
- После аварийного завершения незакрытая сессия попадёт в архив при следующем запуске.
- Старые сессии, созданные до появления архива, переводятся туда при обновлении профиля.

Под текущей сессией находится сворачиваемый **«Архив»** со счётчиком. Архивирование не удаляет запросы, тела или названия. Архив пока не является механизмом сжатия или автоматической очистки диска.

Выбор архивной сессии меняет только просматриваемую историю. Новые запросы продолжают записываться в текущую сессию. В заголовке видна отметка архива; кнопка **«К текущей сессии»** возвращает к записи.

### Переименование

Карандаш рядом с названием открывает переименование. Название сохраняется на диске, длина — до 120 символов; пустое название и управляющие символы не принимаются.

### Очистка трафика

Корзина справа от заголовка трафика очищает **выбранную сессию** после подтверждения. Правила и сама сессия сохраняются. Удаляются её запросы и сохранённые тела. Поздние ответы очищенных запросов не восстанавливают их в списке.

Очистка не ставит запись на паузу: новые запросы могут появляться сразу после неё.

### Удаление сессии

Корзина рядом с названием удаляет старую сессию вместе с её трафиком и телами. Сессию, в которую сейчас идёт запись, удалить нельзя — сначала создать новую. При удалении открытой архивной сессии интерфейс возвращается к текущей.

### HAR

Кнопка экспорта рядом с названием сохраняет **HAR 1.2**:

- экспортируется вся выбранная сессия, независимо от фильтров и лимита видимого списка;
- это снимок на момент экспорта, запись может продолжаться;
- включаются запросы, ответы и доступные сохранённые тела;
- оригиналы и метаданные правил находятся в расширениях `_chls`;
- бинарные тела кодируются в подходящем для HAR виде, отсутствующие/потоковые отмечаются;
- настройки CA и ключи WireGuard в HAR не экспортируются.

Импорт HAR/сессий в CHLS пока не реализован. Импорт JSON-правил — отдельная существующая функция.

<a id="layout"></a>

## 10. Настройка размеров рабочих областей

Перетаскиваемые разделители есть в четырёх местах:

| Разделитель                               | Что меняется                      |
| ----------------------------------------- | --------------------------------- |
| Между sidebar и основной областью         | Ширина боковой панели             |
| Между таблицей запросов и инспектором     | Соотношение двух рабочих областей |
| В «Сценариях» между редактором и журналом | Ширина редактора и журнала        |
| В sidebar между сессиями и хостами        | Высота этих разделов              |

Настройки сохраняются между запусками. При уменьшении окна размеры ограничиваются, чтобы соседняя область оставалась доступной; сохранённое предпочтение не стирается. Изменение размера не очищает историю и не сбрасывает черновик сценария.

Управление:

- потянуть границу мышью;
- двойной щелчок по границе — вернуть исходный размер именно этого разделителя;
- Tab до разделителя и стрелки по его оси — изменить размер;
- Shift + стрелка — крупный шаг;
- Home / End — минимальный / максимальный размер;
- Enter — исходный размер;
- Esc во время перетаскивания — отменить текущий жест.

Редакторы правил — отдельные обычные окна: их размер меняется средствами операционной системы.

<a id="rules"></a>

## 11. Правила: общая логика

В разделе **«Правила»** поддерживаются три вида: Rewrite, Map Local, Blocklist. Есть включение/выключение, изменение порядка, дублирование, импорт и экспорт собственного JSON-формата CHLS. Максимум — 500 правил с уникальными ID. Charles XML не импортируется.

Создать правило можно из раздела правил либо правым кликом по запросу. Во втором случае автоматически подставляются исходные хост, метод, путь и query string.

### Отдельные окна редактора

Редактор не блокирует главное окно: можно копировать данные из запросов, открывать другие правила и переключаться через Alt+Tab. Одновременно доступны несколько разных правил. Повторное открытие того же правила фокусирует уже открытый черновик.

- **«К запросам»** — фокус на главное окно.
- **Ctrl+S** — сохранить правило.
- **Esc** — закрыть редактор без сохранения.
- Закрытие главного приложения закрывает и редакторы.
- Сохранение одного правила не перезаписывает параллельные изменения других правил.

### Условия совпадения

| Поле          | Поведение                                                                                 |
| ------------- | ----------------------------------------------------------------------------------------- |
| Хост          | Без учёта регистра; пусто — любой; `*.example.com` подходит корневому домену и поддоменам |
| Метод         | Конкретный HTTP-метод либо любой                                                          |
| Путь          | Например, `/report`, без query string в новых правилах                                    |
| Query string  | Параметры без начального `?`; пусто — любые параметры                                     |
| Сопоставление | Точное, содержит либо Python regex; применяется отдельно к пути и заполненному query      |

При вставке `https://site.net/report?encrypted_request=1&deviceid=c6ebaf69c6` в поле пути редактор разделит его на:

```text
Хост:         site.net
Путь:         /report
Query string: encrypted_request=1&deviceid=c6ebaf69c6
```

Порядок параметров и их URL-кодирование учитываются: это не сравнение неупорядоченного набора ключей. Если параметры не должны ограничивать правило, очистить поле Query string. Для любого пути — пустой путь и сопоставление «Содержит».

У старых правил `query: null`/отсутствующее поле сохраняет прежнее сопоставление по полному пути с параметрами. Обычный старый путь с query разделяется при открытии в редакторе. Legacy regex автоматически не переписывается.

### Порядок обработки

1. Фиксируются исходное расположение запроса и версия обычных правил.
2. Активный сценарий получает первую возможность обработать запрос.
3. Если сценарий его не обработал, выполняются request-правила сверху вниз.
4. Map Local и Blocklist завершают request-стадию; отправки запроса в upstream не происходит.
5. Для обычного или локально созданного ответа выполняются response/both Rewrite из той же версии правил.
6. Для ответа, обработанного модулем сценариев, обычный response Rewrite пропускается.

Условия обычных правил сравниваются с **исходными** host/path/method, а не с URL после предыдущего Rewrite. Изменение списка правил действует на новые запросы; уже начатый запрос сохраняет свою версию на обе стадии.

Ошибки действий и отсутствие совпадения можно увидеть на вкладке «Правила» инспектора. Ошибка отдельного действия не означает успешную подмену; остальные подходящие действия могут продолжить обработку.

<a id="rewrite"></a>

## 12. Rewrite

Обычный Rewrite содержит одну выбранную операцию. Для цепочки изменений создать несколько правил и расположить в нужном порядке.

| Операция                          | Возможность                                                                                   |
| --------------------------------- | --------------------------------------------------------------------------------------------- |
| Set Header                        | Установить заголовок, создать отсутствующий; также сохраняет совместимость со старым форматом |
| Add Header                        | Добавить экземпляр заголовка                                                                  |
| Modify Header                     | Найти, изменить значение или переименовать заголовок                                          |
| Remove Header                     | Удалить совпавшие заголовки                                                                   |
| Host                              | Изменить реальный хост назначения и HTTP Host/:authority, сохранив порт                       |
| Path                              | Изменить путь, сохранив query string                                                          |
| URL                               | Изменить полный URL                                                                           |
| Add / Modify / Remove Query Param | Добавить, изменить/переименовать или удалить параметры; дубликаты поддерживаются              |
| Response Status                   | Изменить статус ответа, например 200 → 404                                                    |
| Body                              | Поиск/замена текста, включая regex и группы                                                   |
| Поле JSON                         | Изменить или удалить значение по пути вида `data.items.0.enabled`                             |

Операции Host, Path, URL и query применяются к запросу. Response Status — к ответу. Заголовки, Body и JSON могут применяться к запросу, ответу либо обеим стадиям.

В расширенном поиске/замене есть regex, учёт регистра, совпадение значения целиком и замена первого/всех совпадений. Regex использует синтаксис Python. Подстановки: `$1`, `$2`, `${name}`; `$$` означает буквальный `$`.

Для Modify имена заголовков/параметров по умолчанию сопоставляются целиком без учёта регистра; regex позволяет другое сопоставление. Пустой поиск означает любое значение. Пустое поле замены в расширенной форме сохраняет значение; для намеренного обнуления используется **«Заменить значение пустой строкой»**. В Add пустое значение создаёт пустое поле.

Примеры:

| Задача                  | Настройка                                                              |
| ----------------------- | ---------------------------------------------------------------------- |
| Поменять 200 на 404     | Response Status, поиск `200`, значение целиком, замена `404`           |
| Включить JSON-флаг      | Поле JSON `data.enabled`, новое значение `true`                        |
| Изменить текстовый флаг | Body, regex `("enabled":\s*)false`, замена `$1true`                    |
| Переключить окружение   | Modify Query Param: имя `env`, значение `production`, замена `staging` |

Новое значение JSON должно быть корректным JSON: `true`, `42`, `"text"`, `null`, объект или массив. Промежуточные объекты пути должны существовать.

После изменения тела движок обновляет соответствующее кодирование/длину, удаляет устаревшие ETag/Content-MD5. Ответы со статусами 204/304 приводятся к пустому телу. Потоковые и слишком большие тела для Body Rewrite не подходят.

<a id="local-block"></a>

## 13. Map Local и Blocklist

### Map Local

Подменяет ответ содержимым локального файла. Настраиваются условия, файл, Content-Type и HTTP-статус. Файл перечитывается **при каждом совпавшем запросе**: его изменение применяется без повторного сохранения правила.

Размер файла — до 8 MiB. Если файл перемещён, удалён или не читается, причину нужно смотреть в журнале правил инспектора. Файл не копируется внутрь экспорта правил: после переноса на другой компьютер его путь потребуется проверить.

### Blocklist

При совпадении либо возвращает выбранный HTTP-статус с локальным текстом блокировки, либо обрывает соединение без ответа. Это отличается от фокуса, который лишь фильтрует отображение.

Оба вида работают и при паузе записи, пока сам перехват активен. Для HTTPS также нужна включённая расшифровка и корректное доверие CA.

<a id="scenarios"></a>

## 14. Сценарии и язык моков

Раздел называется **«Сценарии»**. Это отдельный модуль для цепочек ответов с состоянием, например заказа. Сейчас одновременно работает **один** документ и один общий текущий этап для подключённых клиентов.

### Рабочий цикл

1. Ввести текст, импортировать его, нажать «Демо» либо загрузить «Шаблон 187».
2. Выбрать домены или **«Все домены»**.
3. Если ответы берутся из файлов — выбрать корневую папку с JSON.
4. Проверить префикс API и строгий режим.
5. Нажать **«Проверить»**.
6. Нажать **«Применить сценарий»**.
7. Отдельно нажать **«Включить сценарий»**.
8. Выбрать свободный режим либо режим по сценарию.

Проверка не включает модуль. Применение целиком проверяет документ и файлы всех этапов, атомарно устанавливает версию и возвращает начальный этап. Если модуль уже был включён, успешное применение сохраняет включённое состояние. Ошибка оставляет прежнюю рабочую версию.

Черновик сохраняется при переходе между разделами интерфейса, но для сохранения документа между запусками его нужно применить. Файлы сценария загружаются в снимок: после их редактирования **применить сценарий заново**. Это отличается от Map Local с перечитыванием файла на каждый запрос.

### Область действия и строгий режим

- Домены — точные имена без схемы и порта.
- «Все домены» убирает ограничение доменом; в сохранённом документе используется `hosts: ["*"]`.
- Пустой список без «Все домены» не является корректной областью действия.
- Префикс API по умолчанию — `/driver/`.
- При строгом режиме неизвестные запросы к выбранным доменам внутри префикса получают **501** и `{"error":"CHLS_MOCK_UNHANDLED"}`.
- Чтобы подменять только перечисленные ручки, а остальные пропускать, выключить **«Блокировать неизвестные запросы внутри префикса»**.
- Известные обработчики могут срабатывать вне строгого префикса; префикс ограничивает блокировку неизвестных ручек.
- Необработанные запросы, которые модуль пропускает, идут в обычный pipeline правил и прокси.

### Два режима

| Режим           | Поведение                                                                                     |
| --------------- | --------------------------------------------------------------------------------------------- |
| **Свободный**   | Этап выбирается вручную. Объявленные триггеры не продвигают состояние                         |
| **По сценарию** | Подходящий HTTP-триггер текущего этапа переключает состояние. Ручные кнопки этапов недоступны |

«Сбросить этап» работает в обоих режимах. Смена режима сохраняет текущий этап. После нового запуска документ и выбранный режим загружаются, но модуль выключен и этап начальный.

### Синтаксис

| Конструкция                               | Значение                                                |
| ----------------------------------------- | ------------------------------------------------------- |
| `модуль "Название"`                       | Имя документа                                           |
| `начало "Имя этапа"`                      | Начальный этап; без явного указания используется первый |
| `файлы "responses"`                       | Подпапка внутри выбранной корневой папки                |
| `путь info = "/driver/order/info"`        | Псевдоним точного пути                                  |
| `общие:`                                  | Ответы, доступные на разных этапах                      |
| `этап "Собирается":`                      | Начало блока этапа                                      |
| `GET info -> 200 {"status":"assembling"}` | JSON непосредственно в строке                           |
| `GET info -> 200 "order.json"`            | JSON из файла                                           |
| `POST "/driver/seen" -> 200 пусто`        | Пустой локальный ответ                                  |
| `при POST confirm -> следующий`           | Триггер перехода на следующий объявленный этап          |
| `при POST confirm -> "Завершён"`          | Переход к конкретному этапу                             |

Комментарии начинаются с `#` на отдельной строке. Тело inline JSON находится в той же строке, что и стрелка. Метод можно опустить — тогда подходят все методы. Поддерживаются GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS и `*`.

Пути сопоставляются точно **без query string**. Внутри этапа ответ для точного метода имеет приоритет над ответом для любого метода. Ответ текущего этапа приоритетнее общего ответа. Дубли одинаковых пути/метода внутри одного блока запрещены.

Коды ответов языка — 200–599. Для 204/304 требуется `пусто`. Файлы должны оставаться внутри выбранного корня и указанной подпапки; выход через `..` не допускается. Это декларативный язык: он не исполняет Python/JavaScript или команды системы.

### Как работают триггеры

В режиме «По сценарию» активный триггер:

1. Совпадает по домену области действия, методу и точному пути.
2. Сам возвращает локальный **200 с пустым телом**.
3. Переводит модуль в целевой этап, если это не подавленный повтор.
4. Записывает переход или причину пропуска в журнал.

Ответ отдельно описывать не нужно. Если для этой ручки задан другой код/JSON, активный триггер всё равно подтверждается пустым 200. Upstream не вызывается. Новые polling-запросы после перехода получают ответы нового этапа; уже выданный ответ не меняется задним числом.

В свободном режиме и для известной ручки без перехода на текущем этапе сохраняется явно заданный ответ; при отсутствии ответа известная ручка триггера может получить пустой локальный 200.

Polling сам не продвигает этап, если на его путь явно не объявлен триггер.

### Повторы и общий этап

Для защиты от двойных переходов используется ограниченный кеш:

- обычно одинаковые клиент, домен, метод, полный путь и тело подавляют повторный переход на 2 секунды;
- при наличии `Idempotency-Key` или `X-Request-ID` повтор того же ID для той же ручки подавляется на 30 секунд;
- новый ID позволяет выполнить следующее логическое действие сразу;
- кеш содержит до 2000 записей;
- сброс, применение, ручной выбор этапа и смена режима очищают защиту.

Это не постоянная история идемпотентности. Для последовательных разных действий на одной ручке используйте разные ID. Сам этап общий для модуля: изоляции независимых заказов по телефонам/пользователям пока нет.

## 15. Пример сценария заказа

Ниже самостоятельный учебный сценарий без внешних JSON-файлов. Его можно вставить в редактор, выбрать «Все домены», применить и включить. Для автоматических переходов выбрать «По сценарию». Это пример механики, а не контракт реального заказа.

```chls
модуль "Учебный заказ"
начало "Собирается"

путь info = "/driver/demo/order"
путь arrive = "/driver/v1/cargo-pro-api/grocery/v1/order/arrive-at-point"
путь confirm = "/driver/v1/cargo-pro-api/grocery/v1/order/exchange/confirm"

общие:
  POST "/driver/seen" -> 200 пусто

этап "Собирается":
  GET info -> 200 {"orderId":"demo-order","status":"assembling"}
  при POST confirm -> следующий

этап "В магазин":
  GET info -> 200 {"orderId":"demo-order","status":"to_store"}
  при POST arrive -> следующий

этап "В магазине":
  GET info -> 200 {"orderId":"demo-order","status":"at_store"}
  при POST confirm -> "Завершён"

этап "Завершён":
  GET info -> 200 {"orderId":"demo-order","status":"completed"}
```

Проверка из PowerShell при HTTP-прокси `8080`:

```powershell
curl.exe --proxy http://127.0.0.1:8080 http://mock.chls.test/driver/demo/order

curl.exe --proxy http://127.0.0.1:8080 --request POST --header "Idempotency-Key: demo-step-1" http://mock.chls.test/driver/v1/cargo-pro-api/grocery/v1/order/exchange/confirm

curl.exe --proxy http://127.0.0.1:8080 http://mock.chls.test/driver/demo/order
```

Сначала ожидается `assembling`, после confirm — `to_store`. Затем POST на arrive переводит к `at_store`, а следующий POST на confirm с новым ID — к `completed`. Домен `mock.chls.test` в этом примере используется как адрес локальной подмены через прокси; запрос должен быть обработан включённым сценарием.

## 16. Шаблон заказа 187

Файл шаблона: `examples/order-187/scenario.chls`. Он доступен кнопкой **«Шаблон 187»** и основан на присланном примере автотеста.

Этапы:

```text
Собирается → В магазин → В магазине → К клиенту → Передать заказ → Вернуться → Завершён
```

Подготовлены ответы для info, polling, state, exchange/init и вспомогательных ручек. Основные переходы используют POST:

- `/driver/v1/cargo-pro-api/grocery/v1/order/arrive-at-point`;

<a id="persistence"></a>

## 17. Что сохраняется между запусками

| Данные/настройка                                            | Поведение                                                                               |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Сессии, названия, история и сохранённые тела                | Сохраняются; старые сессии архивируются                                                 |
| Текущая сессия записи                                       | При каждом запуске создаётся новая                                                      |
| Состояние записи                                            | При запуске включено                                                                    |
| Ручная остановка перехвата                                  | Не сохраняется как запрет автозапуска; следующий запуск снова пробует включить перехват |
| Порты, HTTP/WireGuard, LAN, endpoint                        | Загружаются из сохранённого capture.json                                                |
| Расшифровка SSL                                             | Сохраняется                                                                             |
| Правила и их включённость/порядок                           | Сохраняются                                                                             |
| CA и данные профиля WireGuard                               | Хранятся в профиле движка                                                               |
| Применённый документ сценария, папка, домены, strict, режим | Сохраняются                                                                             |
| Включённость сценария                                       | После запуска выключен                                                                  |
| Текущий этап сценария                                       | Возвращается к начальному                                                               |
| Неприменённый черновик сценария                             | Живёт при навигации в текущем окне, не является сохранённым документом                  |
| Несохранённые черновики правил                              | Не сохраняются при закрытии редактора/приложения                                        |
| Набор хостов в фокусе                                       | Сохраняется и общий для сессий                                                          |
| «Все хосты / В фокусе»                                      | При запуске «Все хосты»                                                                 |
| Тема, выбор Android/iPhone, размеры панелей                 | Сохраняются в localStorage профиля интерфейса                                           |
| Развёрнутость архива, текст поиска, выделенный запрос       | Не следует считать сохранёнными настройками между запусками                             |

<a id="data"></a>

## 18. Где лежат данные, как сделать резервную копию

Авторитетный путь — `app.getPath('userData')` Electron. На Windows обычно это `%APPDATA%\chls` (регистр имени папки значения не имеет). Данные движка находятся в подпапке `engine`.

```text
<userData>/
├── engine/
│   ├── history.sqlite3        # сессии, archived-флаг, summaries/details
│   ├── bodies/                # сохранённые байты сообщений
│   ├── rules.json             # обычные правила
│   ├── capture.json           # настройки слушателей и SSL
│   ├── mock-module.json       # применённый документ сценария и его настройки
│   ├── certificates/          # CA и связанные ресурсы mitmproxy
│   └── engine.log             # лог последнего запуска
└── ...                        # профиль Electron, в том числе localStorage
```

Внутри профиля движка mitmproxy также хранит собственные ресурсы WireGuard. Не нужно ориентироваться только на один известный файл при полном переносе профиля.

### Резервная копия

1. Закрыть CHLS и дождаться завершения движка.
2. Скопировать **всю папку userData**, если нужны и сетевые данные, и настройки интерфейса.
3. Для восстановления работать с закрытым приложением и возвращать согласованную копию профиля.

Копия только `engine` сохраняет сетевые данные, но не гарантирует перенос темы, фокуса и размеров панелей. HAR — экспорт истории, а не полная резервная копия и не способ восстановить её обратно в CHLS.

SQLite использует WAL. Копирование только основного файла открытой базы может дать неполный снимок: поэтому для обычной файловой копии приложение нужно закрыть.

Профиль содержит перехваченные данные и закрытые ключи. Публичный CA из кнопки экспорта и весь каталог `certificates` — разные по содержимому вещи. Лог движка открывается с перезаписью при новом запуске, поэтому нужную диагностику стоит скопировать до следующего запуска.

Map Local и файловые сценарии могут ссылаться на внешние папки. Их тоже нужно перенести; одних настроек с путями недостаточно.

Наличие сохранённого тела зависит от streaming. Лимит 64m в настройках движка не обещает, что тело такого размера будет доступно в инспекторе или для Rewrite. При длительной работе SQLite и файловое хранилище растут; отдельного writer-процесса и ротации пока нет.

### Пока не реализовано

- Breakpoints с ручной остановкой и продолжением запроса/ответа.
- Replay/повтор запросов из истории.
- Отдельный Map Remote как инструмент интерфейса; при этом существующий Rewrite URL/Host уже умеет менять назначение запроса.
- Импорт HAR и восстановление сессий из HAR.
- Импорт правил Charles XML.
- Специализированный просмотр изображений и WebSocket-сообщений.
- Local Capture и автоматическое подключение процессов/системного прокси.
- Менеджер нескольких WireGuard-профилей, ротация peer, подтверждение handshake в UI.
- Независимые состояния сценария для разных телефонов/заказов, несколько активных модулей.
- Переменные, функции и исполняемый JavaScript/Python в языке сценариев.
- Готовая и проверенная macOS-сборка.

Для macOS потребуются сборка Python-движка на macOS, адаптация платформенных команд, подпись/notarization и отдельные проверки. Переносимая структура frontend не означает, что macOS уже поддержана выпуском.

<a id="troubleshooting"></a>

## 20. Частые проблемы

### `Failed to bind UDP socket ... 51820`, `os error 10048`

UDP-порт занят другим слушателем или ещё освобождается после остановки. Выбрать свободный UDP-порт в настройках WireGuard и заново получить профиль/QR. Старый профиль с прежним Endpoint сам не обновится.

Посмотреть владельца порта в PowerShell:

```powershell
Get-NetUDPEndpoint -LocalPort 51820 | Select-Object LocalAddress, LocalPort, OwningProcess
```

Имя процесса можно посмотреть через `Get-Process -Id <OwningProcess>`, подставив найденный PID. Не нужно автоматически завершать неизвестный системный процесс. TCP и UDP — разные пространства портов; проверка TCP не доказывает свободу WireGuard-порта.

### Туннель включён, запросов нет

Проверить перехват, запись, адрес Endpoint, порт профиля, доступность компьютера, брандмауэр, изоляцию Wi-Fi-клиентов и другой VPN на телефоне. Убедиться, что интерфейс не показывает архивную сессию и что поиск/фокус/фильтры не скрывают нужные запросы. Один профиль не использовать одновременно на двух телефонах.

### В браузере HTTPS виден, а в приложении — нет

Проверить доверие CA именно сетевого стека приложения, debug-конфигурацию Android и pinning. Wi-Fi-прокси может игнорироваться приложением; в таком случае для маршрутизации полезен WireGuard, но требования доверия TLS сохраняются. Проверить, что щит SSL включён.

### mitm.it не открывает страницу сертификата

Сначала направить браузер через CHLS. При отсутствии подключения обычное открытие домена не является проверкой CA этого профиля. Альтернатива — «Сохранить CA» в окне подключения.

### Везде `501` и `CHLS_MOCK_UNHANDLED`

Включён строгий сценарий, а запросы не описаны в нём. Отключить блокировку неизвестных запросов, сузить область доменов/префикс или добавить нужные ответы. «Все домены» вместе со строгим широким префиксом расширяет область такой блокировки.

### Ошибка пустого `hosts`

Выбрать хотя бы один домен либо включить **«Все домены»**. Просто оставить список пустым недостаточно.

### Триггер не перевёл этап

Проверить: модуль включён, выбран режим «По сценарию», совпали домен/метод/путь, триггер объявлен именно в текущем этапе, запрос не попал под защиту от повторов. Причина видна в журнале. Ответ 200 сам по себе не доказывает выполнение перехода: повтор тоже подтверждается 200.

### Мок остался прежним после изменения файла

Файлы сценария — снимок на момент применения. Применить документ заново. Для Map Local поведение другое: файл перечитывается на каждый запрос.

### Правило не срабатывает

Проверить включённость, порядок, фазу, метод, исходный хост/путь, query string, выбранное сопоставление и приоритет сценария. Если запрос полностью обслужил сценарий, обычные правила его не меняют. Для тела проверить streaming и размер. Подробности смотреть на вкладке «Правила» инспектора.

### Большой JSON одной строкой

Включить Pretty. В 0.5.3+ он работает и для обрезанного JSON-превью, которое обычный JSON.parse разобрать не может. Само обрезание 256 KiB при этом не отменяется. При необходимости скачать полное сохранённое тело.

### После очистки появляются новые запросы

Очистка не выключает запись. Это могут быть новые запросы приложения. Поздние ответы именно очищенных запросов защищены от восстановления в истории.

### Нет старой сессии в основном списке

Раскрыть «Архив». Основной список предназначен для текущей сессии. Просмотр архива не переключает запись в него.

## 22. Архитектура и карта файлов

```text
React renderer: интерфейс, Zustand, виртуальные списки
    ↕ ограниченный contextBridge
Electron main: окна, IPC, файлы, жизненный цикл, токен API
    ↕ HTTP/WebSocket на 127.0.0.1:<случайный порт>
Python process: FastAPI + mitmproxy DumpMaster + CaptureAddon
    ├── HTTP-прокси / WireGuard
    ├── сценарии и обычные правила
    └── SQLite, тела, настройки, CA
```

Frontend не участвует в обработке каждого пакета. Правила и сценарии выполняются в Python-движке, поэтому пауза записи и навигация интерфейса не отключают подмены.

Внутренний управляющий API привязан к loopback. Случайный Bearer-токен создаётся на запуск в Electron main и не передаётся renderer напрямую. У API нет браузерного CORS-доступа. Renderer работает без Node.js, с sandbox/context isolation; IPC проверяет отправителя и разрешённые маршруты. Перехваченные тела отображаются как текст, а не исполняемый HTML.

Изменения запросов объединяются по ID, события отправляются пакетами примерно раз в 120 мс. При переполнении очереди отправляется `resync`; после переподключения состояние перечитывается.

## 23. Внутренний управляющий API

API предназначен для Electron bridge и тестов. Это не отдельный публичный сервис с фиксированным портом. HTTP-порт прокси `8080` и случайный порт управляющего API — разные вещи.

| Метод и маршрут               | Назначение                                                             |
| ----------------------------- | ---------------------------------------------------------------------- |
| `GET /status`                 | Слушатели, config, запись, текущая сессия, адреса и ошибки             |
| `POST /capture/start`         | Запустить слушатели с CaptureConfig                                    |
| `POST /capture/stop`          | Остановить слушатели и закрыть соединения                              |
| `POST /capture/ssl`           | `{ "enabled": true/false }` — расшифровка TLS                          |
| `POST /recording`             | `{ "enabled": true/false }` — сохранение новых запросов                |
| `GET /wireguard?endpoint=...` | Конфигурация клиента для активного WireGuard-слушателя                 |
| `GET /certificate`            | Публичный CA                                                           |
| `GET /rules`                  | Все обычные правила                                                    |
| `PUT /rules`                  | Сохранить весь список правил                                           |
| `POST /rules/save`            | Атомарно добавить/обновить одно правило по ID                          |
| `GET /sessions`               | Метаданные сессий, включая `archived`                                  |

```json
}
```

Это пример CaptureConfig, а не адреса конкретного пользователя. Документ сценария передаётся полями `source`, `folder`, `hosts`, `scope`, `strict`. Управление: `action` плюс, при необходимости, `stage` или `mode` (`free`/`scenario`). Режим меняется через control, не строкой языка.

## 24. Разработка, проверки и сборка

### Подготовка Windows

Ориентир окружения проекта — Node.js 24 и Python 3.13. Все команды ниже выполняются из корня репозитория.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1
npm run dev
```

Setup создаёт `.venv`, устанавливает зависимости из `requirements.txt`, PyInstaller и выполняет `npm ci`. Dev-команда запускает Vite и Electron; Electron использует `.venv/Scripts/python.exe -m backend`.

### Проверки

```powershell
# TypeScript и production-frontend
npm run build

# Python: правила, сценарии, сессии, HAR и реальные сетевые интеграции
npm test

# Форматирование полного/обрезанного JSON
npm run test:format
```

При последней полной проверке backend было **74 теста**, отдельно форматирование — **5 тестов**. Это исторический результат, а не утверждение, что команды автоматически запускаются при каждом изменении документа.

UI-прогон в разработке: сначала в отдельном терминале `npx vite --host 127.0.0.1`, затем:

```powershell
node scripts/smoke-ui.cjs
```

Для конкретных готовых сборок:

```powershell
$env:CHLS_SMOKE_BUILD_DIR = 'release/0.5.6'
node scripts/smoke-ui.cjs --packaged
node scripts/smoke-ui.cjs --portable

# Дополнительные большие JSON, gzip и длинные строки
$env:CHLS_SMOKE_LARGE_BODY = '1'
node scripts/smoke-ui.cjs --packaged
Remove-Item Env:CHLS_SMOKE_LARGE_BODY
```

UI-прогон использует отдельный профиль, свободные тестовые TCP/UDP-порты и локальный upstream. Он проверяет реальный захват, правила, отдельные редакторы, сертификат/QR, архив, сценарии, размеры панелей, поиск, темы и завершение. Профиль/артефакты — в `build/ui-smoke`. Ошибки фокуса окна или незавершённые асинхронные команды нужно отличать от ошибки функций; в тестах ожидать подтверждённое состояние интерфейса/движка.

Большее тело проверяется на искусственных воспроизводимых ответах. Работа с физическим Android/iPhone, реальным заказом и его контрактами требует отдельной проверки на устройстве.

### Сборка

```powershell
# Frontend + backend + Windows portable, стандартный output release/
npm run package
```

Для выпуска в отдельную версионную папку:

```powershell
npm run build
npm run build:engine
npx electron-builder --win portable --config.directories.output=release/0.5.6
```

В команде указана текущая версия для воспроизведения. Для нового выпуска сначала изменить версию в `package.json` и `package-lock.json`, затем использовать новую папку. Сборка frontend не пересобирает Python автоматически. После изменений backend нужно обновлять `runtime/chls-engine` через `npm run build:engine`, иначе EXE может получить старый движок.

Для проверки именно собранного движка:

```powershell
$env:CHLS_TEST_ENGINE = (Resolve-Path 'runtime/chls-engine/chls-engine.exe').Path
npm test
Remove-Item Env:CHLS_TEST_ENGINE
```

`dist`, `runtime`, `build`, `release`, `.venv` и `node_modules` — генерируемые каталоги, они исключены из Git. Старые версионные сборки остаются в `release/`. Текущая схема сборки использует стандартный значок Electron; собственный значок/подпись не следует считать настроенными.

### Полезные переменные окружения

| Переменная              | Где используется                                            |
| ----------------------- | ----------------------------------------------------------- |
| `CHLS_USER_DATA`        | Меняет профиль Electron; удобно для изолированных UI-тестов |
| `CHLS_DATA`             | Папка данных Python-движка; штатно задаётся Electron        |
| `CHLS_TOKEN`            | Случайный секрет API на запуск; штатно задаётся Electron    |
| `CHLS_VERSION`          | Версия приложения для метаданных экспорта                   |
| `CHLS_TEST_ENGINE`      | Путь к EXE движка для интеграционных тестов                 |
| `CHLS_SMOKE_BUILD_DIR`  | Версионная папка для UI smoke готовых сборок                |
| `CHLS_SMOKE_LARGE_BODY` | `1` включает проверки больших тел                           |

Не нужно фиксировать рабочий токен API, приватный CA, WireGuard-ключи или пользовательскую историю в исходниках/документации.

## 26. Как поддерживать документ актуальным

При изменении функций обновлять этот файл, краткий `README.md` и при необходимости `ARCHITECTURE.md`. Проверять не только тексты интерфейса, но и модели/API, сохранение настроек, ограничения и содержимое реально упакованного движка.

Не считать готовой функцией пункт из обсуждения или будущего плана. Для UI сохранять принципы `AGENTS.md`: компактное desktop-приложение, нейтральные цвета, один сдержанный акцент, списки/таблицы, минимальные разделители, доступные клавиатурные действия и читаемый текст.

Документ описывает **0.5.6**. Если версия кода выше, прежде чем использовать его как единственный источник, сверить `package.json`, Git и актуальные исходники.
